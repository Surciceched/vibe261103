## 1. 배경 및 목적

개발자 개인의 기술 역량과 작업물을 한 페이지에서 신뢰감 있게 보여주는 포트폴리오 웹사이트를 만든다.
이력서 PDF를 보내기 전 단계에서 "이 사람이 무엇을 할 수 있는지"를 60초 안에 전달하는 것이 목표다.

### 해결하려는 문제
- 구인 담당자·클라이언트가 기술 스택과 실제 결과물을 빠르게 확인할 자리가 없다.
- GitHub 저장소만으로는 프로젝트의 맥락(왜 만들었고, 무엇을 담당했는지)이 전달되지 않는다.
- 연락 경로가 흩어져 있어 문의가 유실된다.

## 5. 기능 요구사항

### 5.1 Hero (우선순위: P0)
- 이름, 직함, 한 줄 소개("Python · HTML5 · iOS 개발자").
- 주요 CTA 2개: `프로젝트 보기`, `이메일 문의`(mailto:mami4226@naver.com).
- 배경은 가벼운 CSS 그라디언트 또는 캔버스 애니메이션(모바일에서는 정적 처리).

### 5.2 About (P0)
- 3~5문장 자기소개, 경력 연차, 관심 영역.
- 프로필 이미지(WebP, 2배수 해상도 대응).
- 이력서 PDF 다운로드 버튼.

### 5.3 Skills (P0)
세 갈래로 그룹화하고 각 항목은 숙련도 라벨(주력 / 능숙 / 경험 있음)로 표기한다. 퍼센트 막대는 근거가 없어 사용하지 않는다.

| 그룹 | 예시 항목 |
| --- | --- |
| Python | FastAPI, Django, pandas, 자동화 스크립트, 테스트(pytest) |
| HTML5 / Web | HTML5, CSS3, JavaScript(ES2022), 반응형 레이아웃, 접근성 |
| iOS | Swift, SwiftUI, UIKit, App Store 배포, Core Data |

### 5.4 Projects (P0)
- 카드 그리드(데스크톱 3열 / 태블릿 2열 / 모바일 1열).
- 카드 구성: 썸네일, 제목, 1줄 요약, 기술 태그, 담당 역할, 링크(GitHub / App Store / 데모).
- 필터: `전체 / Python / Web / iOS` 태그 버튼.
- 데이터는 `data/projects.json`으로 분리해 콘텐츠 수정 시 HTML을 건드리지 않는다.

### 5.5 Experience (P1)
- 수직 타임라인: 기간, 소속, 역할, 핵심 성과 2~3줄.

### 5.6 Contact (P0)
- 이메일 `mami4226@naver.com`을 복사 버튼과 mailto 링크로 함께 제공.
- GitHub, LinkedIn, App Store 개발자 페이지 링크.
- 문의 폼은 v1에서 제외(백엔드·스팸 대응 비용). 필요 시 v2에서 서버리스 함수로 추가.

### 5.7 공통 (P0)
- 다크/라이트 테마 토글, 선택값 localStorage 저장, 기본값은 OS 설정 따름.
- 섹션 스크롤 스파이가 적용된 상단 내비게이션.
- 404 페이지.

## 7. 기술 스택 (제안)

| 영역 | 선택 | 근거 |
| --- | --- | --- |
| 프론트엔드 | HTML5 + CSS + 바닐라 JS (정적) | 주력 분야와 일치, 빌드 복잡도 최소, 로딩 빠름 |
| 콘텐츠 | JSON 데이터 파일 | 프로젝트 추가가 쉬움 |
| 배포 | GitHub Pages 또는 Netlify | 무료, 자동 배포, 커스텀 도메인 지원 |
| 분석 | 선택 사항(Plausible 등 쿠키 없는 도구) | 개인정보 부담 최소 |

> 향후 서버 기능(문의 폼, 방문 통계)이 필요해지면 Python/FastAPI 기반 API를 별도 추가한다.
