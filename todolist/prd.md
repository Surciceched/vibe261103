# PRD: 오늘의 할일 웹페이지

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 초안 (설계 단계, 구현 전) |
| 작성일 | 2026-11-02 |
| 대상 플랫폼 | 웹 브라우저 (데스크톱, 모바일) |

## 1. 개요

오늘 해야 할 일을 빠르게 적고, 체크하고, 진행 상황을 한눈에 확인하는 1인용 웹페이지다. 회원가입이나 서버 없이 브라우저에서 바로 동작한다.

### 1.1 해결하려는 문제

- 일반 할일 앱은 프로젝트, 태그, 일정 등 기능이 많아 "오늘 할 일"만 적기에는 번거롭다.
- 끝내지 못한 일이 쌓이면서 오늘 집중할 일이 흐려진다.

### 1.2 목표

- 페이지를 열고 5초 안에 첫 할일을 추가할 수 있다.
- 오늘 할일의 진행률을 화면에서 바로 확인할 수 있다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 유지된다.
- 어제 끝내지 못한 일을 오늘로 옮길지 직접 결정할 수 있다.

### 1.3 비목표 (이번 범위에서 제외)

- 회원가입, 로그인, 기기 간 동기화
- 여러 사람이 함께 쓰는 공유, 협업 기능
- 미래 날짜 일정 관리, 반복 할일, 캘린더 보기
- 푸시 알림, 리마인더

## 2. 대상 사용자

매일 아침이나 업무 시작 전에 그날 할 일을 정리하는 개인 사용자. 설치나 계정 생성 없이 가볍게 쓰기를 원한다.

## 4. 기능 요구사항

### 4.1 P0: 필수 (MVP)

**FR-1. 오늘 날짜 표시**
- 페이지 상단에 오늘 날짜와 요일을 표시한다. 예: `2026년 11월 2일 월요일`
- 날짜는 사용자 기기의 현지 시간을 기준으로 한다.

**FR-2. 할일 추가**
- 입력창에 내용을 적고 Enter 또는 추가 버튼으로 등록한다.
- 앞뒤 공백을 제거하며, 빈 내용은 등록하지 않는다.
- 최대 길이는 200자다.
- 등록 후 입력창을 비우고 포커스를 유지해 연속으로 입력할 수 있게 한다.
- 새 항목은 미완료 목록의 맨 아래에 추가한다.

**FR-3. 완료 처리**
- 체크박스로 완료와 미완료를 전환한다.
- 완료된 항목은 취소선과 흐린 색으로 표시하고, 미완료 항목 아래로 이동한다.

**FR-4. 수정**
- 항목을 더블클릭하거나 수정 버튼을 누르면 인라인 편집 모드로 전환한다.
- Enter 또는 포커스 이탈 시 저장하고, Esc를 누르면 취소한다.
- 내용을 모두 지우고 저장하면 변경을 취소하고 원래 내용을 유지한다.

**FR-5. 삭제**
- 삭제 버튼으로 즉시 삭제한다.
- 삭제 후 5초 동안 "되돌리기"가 포함된 토스트를 표시한다.

**FR-6. 진행률 표시**
- `완료 수 / 전체 수`와 진행률 막대를 표시한다. 예: `3 / 5 완료`
- 할일이 없으면 진행률 대신 빈 상태 안내 문구를 표시한다.

**FR-7. 데이터 저장**
- 모든 변경 사항을 `localStorage`에 즉시 저장한다.
- 새로고침과 브라우저 재시작 후에도 데이터를 복원한다.

### 4.2 P1: 중요

**FR-8. 미완료 항목 이월**
- 앱을 열었을 때 이전 날짜에 미완료 항목이 있으면 상단에 배너를 표시한다. 예: `어제 못 끝낸 일 2개가 있어요`
- 배너에서 `오늘로 가져오기`와 `버리기`를 선택할 수 있다.
- 자동으로 이월하지 않는다. 쌓이는 일이 아니라 오늘 할 일을 사용자가 고르게 하기 위해서다.
- 페이지를 열어 둔 채 자정이 지나면 탭이 다시 활성화될 때 날짜를 다시 확인해 오늘 화면으로 전환한다.

**FR-9. 순서 변경**
- 미완료 항목을 드래그 앤 드롭으로 재정렬한다.
- 터치 환경과 키보드 사용자를 위해 위/아래 이동 수단도 제공한다.

**FR-10. 완료 항목 관리**
- 완료 항목 접기와 펼치기를 제공하고, 상태를 저장한다.
- `완료 항목 지우기`는 확인 단계를 거치거나 FR-5의 되돌리기를 제공한다.

### 4.3 P2: 있으면 좋음

**FR-11. 다크 모드**: 시스템 설정을 따르되 수동 전환을 제공한다.

**FR-12. 모두 완료 시 피드백**: 전체 완료 시 축하 문구를 표시한다. `prefers-reduced-motion` 설정 시 애니메이션은 생략한다.

| 구분 | 요구사항 |

## 7. 기술 설계

### 7.1 기술 스택

바닐라 HTML, CSS, JavaScript(ES Modules)를 사용하며 빌드 도구와 외부 런타임 의존성을 두지 않는다. 화면이 하나이고 상태가 단순해 프레임워크의 이점이 적고, 파일을 정적 호스팅에 그대로 올릴 수 있기 때문이다.

참고: ES Modules는 `file://`로 직접 열면 차단되므로 로컬 확인에는 간단한 정적 서버(예: `npx serve`)가 필요하다.

### 7.2 구조

단방향 흐름으로 구성한다: 사용자 입력 → 상태 변경 → 저장 → 화면 렌더링.

```
todolist/
├── prd.md
├── index.html        # 페이지 뼈대
├── css/
│   └── style.css     # 스타일, 다크 모드 변수
└── js/
    ├── app.js        # 초기화, 이벤트 연결
    ├── store.js      # 상태 변경 로직 (순수 함수 중심)
    ├── storage.js    # localStorage 읽기/쓰기, 스키마 검증
    ├── view.js       # DOM 렌더링
    └── date.js       # 현지 날짜 계산
```

### 7.3 데이터 모델

```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~200자
  completed: boolean;
  date: string;          // 소속 날짜, 현지 기준 "YYYY-MM-DD"
  order: number;         // 같은 날짜 내 정렬 순서
  createdAt: string;     // ISO 8601
  completedAt: string | null;
}

interface AppData {
  version: 1;            // 스키마 버전, 추후 마이그레이션에 사용
  todos: Todo[];
  settings: {
    theme: "system" | "light" | "dark";
    completedCollapsed: boolean;
  };
}
```

- `localStorage` 키: `today-todo:v1`
- 날짜는 `toISOString()`을 쓰면 UTC로 변환되어 한국 시간 오전 9시 이전에 전날로 계산되므로, 반드시 현지 시간의 연, 월, 일로 생성한다.

### 7.4 핵심 동작 규칙

| 상황 | 동작 |
| --- | --- |
| 앱 시작 | 데이터 로드 → 오늘 날짜 계산 → 이전 날짜의 미완료 항목 확인 → 렌더링 |
| 오늘로 가져오기 | 해당 항목의 `date`를 오늘로 변경하고 `order`를 오늘 목록 뒤에 이어 붙임 |
| 버리기 | 이전 날짜의 미완료 항목 삭제 |
| 데이터 보관 | 이전 날짜의 완료 항목은 앱 시작 시 삭제 (기록 보기 기능이 없으므로 보관하지 않음) |
| 저장 데이터 손상 | JSON 파싱이나 스키마 검증 실패 시 원본을 `today-todo:backup`에 복사하고 빈 상태로 시작 |
| 저장 실패 | 메모리 상태는 유지하고 경고 배너 표시 |
| 다중 탭 | `storage` 이벤트로 다른 탭의 변경을 감지해 다시 렌더링 |

## 8. 수용 기준

- [ ] 할일을 추가, 체크, 수정, 삭제할 수 있고 새로고침 후에도 유지된다.
- [ ] 공백만 입력하면 등록되지 않고, 200자를 넘게 입력할 수 없다.
- [ ] 삭제 후 5초 안에 되돌리면 원래 위치로 복원된다.
- [ ] 진행률이 추가, 완료, 삭제 시 즉시 갱신된다.
- [ ] `<script>` 등 HTML을 입력해도 일반 텍스트로 표시된다.
- [ ] 기기 시계를 다음 날로 바꾸면 이월 배너가 표시되고, 두 선택지가 정상 동작한다.
- [ ] 자정 직후와 오전 9시 이전에도 날짜가 현지 기준으로 올바르다.
- [ ] 저장 데이터가 손상되어도 앱이 멈추지 않고 빈 상태로 시작한다.
- [ ] 키보드만으로 모든 P0 기능을 사용할 수 있다.
- [ ] 360px 너비에서 가로 스크롤이 생기지 않는다.

## 11. 확인이 필요한 사항

아래 항목은 작성자가 기본값으로 가정했다. 구현 전에 확인이 필요하다.

1. **저장 방식**: 로그인 없는 `localStorage` 전용으로 가정했다. 여러 기기에서 동기화가 필요하면 백엔드 설계가 추가된다.
2. **이전 기록**: 지난 날짜의 완료 항목을 삭제하도록 가정했다. 기록 보기가 필요하면 보관 정책과 화면을 추가해야 한다.
3. **이월 방식**: 자동 이월이 아니라 사용자가 선택하는 방식으로 가정했다.
4. **기술 스택**: 프레임워크 없는 바닐라 JS로 가정했다.
